# 薪资计算与结算

## 计算原则

成员方案默认应用到所选整月或完整结算周期，包括该范围内已经录入的工时。页面可用月份快捷填入、已有周期或明确起止时间指定范围；结束时间不包含在计薪范围内。接口通过 `effectiveFrom` 和 `effectiveTo` 指定完整范围，时薪直接按配置单价计算，启用的倍率和奖励单独参与计算。相同范围再次保存会替换本期设置，范围外已有价格和未来安排继续保留；已结算或锁定的范围不能直接修改。仅明确选择“仅从指定时间起”时保留按生效时间分段的行为。

完整范围内的固定补贴在该范围结束前的最后一个本地日期计入，按生效时长折算的补贴以原配置完整范围为分母。自定义周期即使在月中结束，月度预估也会计入它的固定补贴；跨月查看不会重复折算。该范围新设的周奖励只累计范围内的工时，保持月度预估与对应周期计算一致。

完整范围的月薪、周期固定金额及混合方案固定部分按配置金额计入。查看其中某一个自然月时，固定部分以原配置完整范围为分母，仅分配该月所占金额，避免跨月范围在两个页面各计一次全额。工时以组织时区的自然月裁剪，并扣除该月范围内的休息；报销按所属结算周期的最后一个本地日期归属月份，不把其他月份的报销重复带入。当前规则为 `payroll-engine-v11-explicit-pay-period`；保存方案后需要更新尚未确认的计算，已确认的文件继续保留原始字节。

薪资计算以 PostgreSQL 的已审核工时和版本化薪资方案为事实来源。实际金额采用十进制字符串与 `BigInt` 计算。工资、奖励和每项同名补贴分别汇总后四舍五入到分，再把尾差分配回组成明细；报销与人工调整按单据舍入，最终金额由这些分币金额相加。新保存的金额及页面、CSV、Excel 和 AI 工资事实统一保留两位小数，审计追踪保留原始金额。预测图表的统计数值不作为正式计薪依据。

每次计算都会保存：适用薪资方案版本、费率规则、工时版本、调整项、明细构成和输入哈希。之后即使规则被编辑，也可以解释某张工资单为何得出该金额。

## 周期状态

|状态|允许操作|含义|
|---|---|---|
|open|配置、计算|尚未锁定的周期|
|pending_confirmation|查看、统计表下载、复核、重新计算|已有未确认计算快照|
|settled|生成工资单、导出、只读查看|已结算，不能直接复算|
|locked|只读、审计、发起更正|最终锁定，业务事实不可直接修改|

工资周期覆盖按真实时间区间切分的工时。休息区间从可支付区间中扣除；跨日、夜间、周末、节假日、加班等规则按优先级、叠加策略与规则版本计算。算法发现净时长和休息区间不一致、缺少生效方案或周期已锁定时会停止并给出冲突，而不会猜测金额。

## 结算与更正

结算前需要复核异常、待审核工时和人工调整。结算将工资单与明细快照固定，并锁定本周期内已批准工时。锁定后不允许静默修改；更正走申请、审核和“下期补发/扣回”的链路，确保历史工资单、审批和审计记录可复算。

已锁定记录只有原记录所属成员可以发起更正。申请会保存完整的拟议工时结构（开始/结束、休息、工作内容与结果、可见性、项目关联）和更正原因，原始锁定事实不会被覆盖。审核人必须拥有该工时对应组织单元或项目范围的 `work.review` 授权，且不能审核自己的申请；驳回需要写明审核说明。批准但不涉及金额时只形成审核结论；若审核人明确填入非零补发/扣回金额，服务端才会在原周期之后的首个开放周期创建调整，货币由该成员在目标周期的有效薪资方案决定。缺少原周期、开放周期或有效薪资方案时系统会拒绝操作，不会猜测金额或币种；每一步都写入审计日志。

## 操作检查清单

1. 确认组织时区、周期开始/结束边界和生效薪资方案。
2. 处理待审核、异常或冲突工时；不要将不确定工时直接当作已批准。
3. 运行计算，检查输入哈希、规则版本、明细与调整原因。
4. 获得授权后结算并锁定；导出的敏感字段仍遵循调用者 scope。
5. 定期做恢复演练，确保备份中的薪资快照、工时版本和审计日志可一起恢复。


## 补贴计入方式与报销

普通补贴按每个成员独立设置的金额，每个周期计入一次。`period_end`、旧配置的缺省值与旧界面的 `daily` 均采用这一固定金额规则；同为 168.19 的配置不会因为计薪类型、本期内生效日期或本期长度不同而得到不同补贴。周期结束时生效版本中的同名补贴替代此前版本，不叠加；方案完全在周期外、已结束且期末不再适用的项目不会凭空计入。同一版本不能重复设置同名补贴，不同名称的真实项目分别计入。

按生效时长折算仍可显式选择，但必须使用新选项 `prorated`，页面明确提示其金额随生效日期变化。保存旧客户端传入的 `daily` 时规范化为 `period_end`；编辑未重存的旧配置也显示固定金额。新规则为 `payroll-engine-v10-fixed-member-subsidies`，计算追踪同时保留原配置的分配值、实际采用的政策、配置金额、生效区间和舍入规则。全额项列在周期末，不作为工作增长的训练数据。老板可以指定周期起止，整月是一种快捷选择；显式折算以实际周期为范围。

员工在“我的报销”页创建报销草稿，再上传文件或添加链接、文字凭证；审批人员在“审批 → 报销审批”处理他人待审申请。个人列表仅显示本人的记录。提交要求至少一项已核验且非私有的证据，未完成上传的文件会阻止提交。草稿和待审申请可以撤回；驳回后保留申请与凭证，新申请重新提交。审批由组织范围的 `payroll.settle` 权限控制，不允许申请人审批自己；普通工时审核权限不会自动获得报销权限。

批准时选择开放周期，校验申请人的有效薪资方案与币种，生成一条正数 payrollAdjustment。已有活动计算批次或已结算的周期不能加入新报销，需先取消未结算批次或选择其他开放周期。报销审批采用行锁与版本校验，防止重复入账；提交后凭证在服务层及数据库层冻结。工资计算保存前会复核调整项，避免并发获批的报销漏入快照。归属于本月周期的获批报销在个人看板独立显示并进入预估总额，不把上月报销带入下月，不增加工时或训练未来薪资增长。周期锁定后申请显示已结算。

报销功能依赖已有的 `0012_hot_korg.sql` 迁移；部署按既有配置运行 `pnpm db:migrate`，应用全部已有迁移。此次金额修复没有新增迁移或批量修改历史账单。

## 老板指定周期与直接统计表下载

结算起止由老板指定，月份是整月快捷填入。新导出的 Excel 保留“薪资总览”“周期工作记录”“工资组成”“报销明细”四张表。薪资总览和 CSV 使用相同精简字段：员工、薪资周期、起止时间、已批准与待审工时、工作工资、奖励、补贴、已批准报销、其他调整、最终金额和金额状态。文件不再展示成员编号、外部编号、时区、币种、方案版本、批次版本、计算追踪和校验信息，也不再增加证据目录和规则来源表。跨月工作记录仅显示所选周期内的起止时间及扣除休息后的净工时；原始事实继续在平台保存。缺方案、预估和待复核均明确标记。统计下载不锁定周期，源数据变化须更新计算；已确认历史文件按原字节重取。

未确认的旧规则账单必须先更新计算，不能沿用旧金额确认交接；已确认原文件仍保留原字节、批次号和 SHA-256，修正沿用审计更正流程。统一补贴、历史单价与金额精度的实例及验收范围见 [金额修复与核对说明](payroll-money-fix-2026-10-01.md)。
