# 全量设计覆盖矩阵

本文件以《工作时间与工作智能管理平台_全量产品与交互设计报告》为验收基线。它只记录已经能够从数据库、服务端接口、前端交互和测试中验证的能力；数据库里存在一张表、前端出现一个入口，均不单独算“完成”。

状态定义：

- **已实现**：主链路有真实持久化、服务端权限/校验和对应界面。
- **部分实现**：核心链路可用，但设计报告要求的分支、交互或验收项仍缺失。
- **未实现**：当前没有可交付的完整链路；不得在产品说明中宣称已完成。
- **外部配置**：代码链路已实现，但生产环境需要第三方凭据或基础设施后才可用。

## 当前结论

系统已经是可部署的真实业务应用，不是静态 Demo；但它还没有达到设计报告所定义的“全量完成”。当前最稳固的是账号与组织基础、工时事实、审批、项目版本操作、薪资核心计算、实时事件和附件安全传输骨架。最主要的缺口集中在分析图表全集、AI 四层任务、提醒规则全集、后台多格式导出、完整离线冲突处理和运维恢复演练。

## AI 配置与调用核对

- 配置读取和写入都会在服务端查询 `organization_owners`，不能依赖前端隐藏按钮；非唯一 Owner 返回 403。
- API Key 使用独立 `AI_CONFIG_ENCRYPTION_KEY` 加密，浏览器只看到“已配置/未配置”，不会收到密钥原文。
- Worker 使用 OpenAI-compatible `POST {baseUrl}/chat/completions`，发送 Bearer、`model`、`temperature: 0.2`、`max_tokens` 和严格 JSON 消息；输出在入库前再次做结构校验。
- 默认 `glm-4.7-flash` 是当前智谱官方接口列出的有效低成本模型。设计报告提到的 `glm-5.3-flash` 当前不在官方模型枚举中，因此不能为了字面一致而默认调用一个未确认存在的模型。
- “已配置”不等于“供应商实时健康”。真实可用性的最终验收必须由 Owner 生成一份报告并确认 Worker 完成；供应商错误会明确失败，绝不生成伪报告。

## 发布门槛

每次声称某一行升级为“已实现”前，至少要同时满足：数据库迁移可重复执行、API 服务端权限测试、核心状态机/金额单元测试、桌面和移动关键路径 E2E、空/错/加载状态、Render 构建与健康检查，以及无真实账号、密钥或虚拟业务数据进入 Git。
