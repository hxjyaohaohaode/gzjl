# 工时记录、审批与薪资交接升级

本次改动建立在既有登录、组织、项目、计时、证据、审批、薪资、AI、通知及后台导出的基线上。平台记录工作并生成外部发薪依据；导出和锁定不表示已经付款。

## 老板设置提交规则

进入「我的薪资」管理页面，在「老板设置 · 最晚提交与补录期限」中配置：

- 手工补录最多追溯 0–366 天，默认 7 天；0 表示组织时区当天，其他值从当前时刻回溯对应天数。
- 是否启用每月最晚提交、当月或次月截止、某日或最后一天以及时分。例如当月最后一天 23:30。
- 每条记录按开始时间在组织时区的月份归属；月末和不足指定日的短月份自动处理。达到截止时刻即停止历史补录、恢复及提交。
- 只有当前组织所有者可以保存。并发保存检测规则版本，其他成员只能读取。所有规则变更保留审计。

组织尚未保存新规则时，继续读取成员既有有效工作预期中的补录天数；老板保存后以组织规则为准。新规则只校验后续操作，已有事实与计时不会被删除。计划转真实工时也遵守规则。历史档案导入仍使用原有独立授权、预览、确认与审计路径。

结算周期的「结算截止 / 计划导出时间」与本规则具有不同用途：前者组织审批和导出安排，后者限制成员补录、恢复和提交。设置次月截止可容纳跨月工作后的核对；不能把未发生的工作批准为事实。

## 首次使用、每天记录与修复

首页提供从计薪方案及生效时间、记录、可提交证据、组织审核到形成导出依据的短路径，并展示整个当前结算周期的全部记录状态。未建立正式周期时明确以组织时区本月作为统计范围。

记录中可核对未提交、退回原因、未核验证据、未来结束时间与异常。定位链接包含记录编号与版本；版本变化时提示重新核对。修复入口包括编辑草稿、撤回待审、归档误填并恢复、审批更正申请及原有已锁定跨周期调整。恢复重新检查重叠、补录期限及结算锁定，不覆盖已导出依据。经审批修复未锁定事实后生成新版本草稿，由成员重新核对并提交。

编辑或申请更正会滚动到实际编辑表单。归档记录支持分页恢复。大量长内容使用可换行的容器；列表预览可以收起，完整事实和版本仍可查看。

## 审批与成员动态

审批列表展示提交人、唯一成员编号、等待时长及相交开放周期的计划导出时间，支持服务端按临近导出、等待最久和异常排序后分页。打开记录可查看当前权限内该成员在记录所属月份的各类工作状态、组织成员状态、可见计时状态、项目节点、相邻及重叠时段、证据与历次审批说明。相邻时段和版本历史分别明确最多最近 100 条 / 版，避免将部分列表误当全量。

组织审核者及成员本人可以查看进行中的计时状态；项目或部门审核者的事实范围仍受原授权限制。私有附件保持私有。成员动态按作者、项目、正文预览、时间与可展开完整内容及附件呈现。

## 可靠薪资交接与完整工作单

每次导出先选择结算周期及批次、逐行核对人员和金额，再确认身份匹配与异常影响。缺少方案、待审、待处理更正、预估 / 待复核金额和未就绪批次会阻止确认。未提交、退回及异常列为可回看事实。预览后发生数据或外部人员映射变化时，旧预览不能确认。保存身份映射或更新整批预览期间，确认控件暂停并提示重新核对，避免提前确认随后失效。历史周期结束后才加入、且没有该周期记录或账单的成员不会阻止旧月份导出。

确认操作在事务中生成并保存以下两个原文件，同时锁定该批次依据：

1. 汇总 CSV：成员 UUID、确认时的外部人员编号、姓名、币种、工时、应计 / 调整 / 最终金额、周期范围、时区、规则和批次号。
2. 完整 Excel：薪资汇总、工资组成（工资、补贴、奖金、扣减、更正、报销调整）、报销明细、工作提交单、工作证据目录、规则与来源。同一文件包含工资明细与提交工作依据，不需要人工拼表。

CSV 使用 UTF-8 BOM，阻断文本公式注入并保留合法负数金额。Excel 金额采用精确十进制文字，避免大额浮点改写；数字工时可以计算。长文本超过单元格容量时完整分段保留，emoji、字面转义串及 XML 控制字符采用可还原编码。表格设冻结表头、筛选、换行、打印页脚和来源编号。

批次保存确认时的规则版本、输入摘要、预览摘要、身份与金额快照，以及原 CSV / Excel 的文件名、字节数和 SHA-256。以后重取原文件不根据改名、改编号或修改后的事实重新生成；浏览器下载时再次校验。预览从数据库只取必要快照与文件元数据，CSV 下载也不加载整个 Excel。完整 Excel 下载同时要求组织薪资结算和组织全文工作查看权限。旧批次若没有完整工作簿，只提供原来保存的文件并明确说明，不能伪造历史文件。

姓名不足以识别同名成员。默认外部编号采用成员 UUID，管理员须按实际发薪平台规则保存唯一外部编号并确认列格式。当前未获得该外部平台的导入模板，不能承诺任意平台都能直接接受当前列顺序。报销已包含在调整及最终金额中，不应再次加总。

## 任意历史范围与选择性数据导出

工作记录、数据分析和成员薪资支持选择任意历史单日、整月或起止日期；数据分析还可按成员、部门、项目、节点、类型、状态及来源组合定位。历史年份不限，每次日期范围最多 366 天。管理薪资按月份筛选周期，每个周期独立核对和导出，因此可以单独取出某月账单。

按组织时区自然日选取，结束日期包含当天，内部换算为 `[from, to)`。相交记录保留完整事实时段；`netSeconds` 表示整条净工时，`rangeNetSeconds` 单独表示所选范围内扣除休息后的有效完整秒数。跨界工时不能直接拿整条时长相加。项目 / 节点选择同时匹配多项目关联，避免遗漏非主节点的事实。

CSV / JSON 直接导出和后台 CSV / JSON / Excel / PDF 接受同一筛选条件，并分别执行数据与导出权限的交集检查。超过 5 万条或 25 MiB 文字时明确要求拆分月份、成员或项目，不静默截断。完整薪资工作簿超过 32 MiB 会撤销确认事务并提示缩短周期，避免留下不完整文件。

## 证据上传与工作智能

文件 SHA-256 分片计算并使用独立 Web Worker，避免大视频一次占用同等大小的 JS 内存；不支持 Worker 的环境使用分片计算。上传显示校验 / 上传进度，支持逐件重试。已上传而核验失败时保留回执，只重试核验；原有文字和链接证据作为其他可核对入口。后端私有存储、真实文件大小与摘要验证及有限签名仍保留。

AI 依据当前页面与当前权限组织事实，区分已批准、待审、预估和依据已导出；不得把导出表述为付款。摘要及关键结论携带逐条可点击来源。捏造、无效或缺少来源的关键输出不作为可靠报告保存。报告完整来源清单分批写入，不因模型输入缩减而丢失来源；模型输入确有裁剪时明确标记。

阅读旧报告时重新检查当前权限、源版本、范围内增删记录和薪资导出状态，提示旧结论需要重新生成或复核。周回顾与 AI 草稿可以编辑校对，确认后保存个人文件，任何编辑取消原确认，不自动提交审批或改动源记录。

## 部署与复验

仍使用 Node.js 24+、pnpm 11+、PostgreSQL 17+ 和既有 Render Web / Worker 配置。此次新增迁移为 `0014_parched_praxagora.sql`，只增加薪资交接身份与批次表；提交政策存入组织已有 settings。先做数据库备份，再执行 `pnpm install --frozen-lockfile`、`pnpm db:migrate`、`pnpm build`，重启 Web 和 Worker。Render Blueprint 的既有 `preDeployCommand` 会执行迁移。

本地复验命令：`pnpm check`、`pnpm test:e2e`、`pnpm test:live`、`pnpm test:upgrades`、`git diff --check`。真实浏览器测试使用隔离临时数据库及本地对象存储服务，覆盖正式 API、生产前端、多个设备尺寸以及 Firefox / WebKit。测试账号和文件仅存在于隔离测试运行时，不进入业务数据库。具体结果见同次交付的验收记录。

验收不能替代真实 Render 发布后的检查：实际 S3 / B2 CORS、权限、签名、AI 供应商响应及外部发薪平台导入需在组织真实配置上验收。本次源码交付不表示生产服务已经发布新版本。最终测试范围与结果见 [交付验收记录](acceptance-2026-10-01.md)。
