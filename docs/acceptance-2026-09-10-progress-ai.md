# 多项目进度与 AI 配置验收（2026-09-10）

## 已实现行为

- 单条工时可跨项目关联多个节点，主关联只从已选节点中选择。每个已选节点可独立选择是否更新完成度，支持数字、滑块和快捷百分比。
- 自动汇总节点可从自身子树添加具体任务；切换项目、主关联不会丢失其他节点的输入，移除关联会清除对应的待更新进度。
- 工时与全部节点进度在一个事务内保存。非法、无权限或自动汇总节点导致整笔回滚；保留审计和版本，不重复累计工时。
- 修改旧草稿的文字不会重放历史完成度，计划不修改项目事实；原单节点 API 输入仍兼容。
- Owner 可在系统内保存 Base URL、模型、Key、输出 Token、超时、尝试次数、Temperature、Top P、Token 参数和响应格式。支持带斜杠的模型名及完整 Chat Completions 地址。
- API 连接测试和 Worker 共用整套配置解析及请求逻辑。支持省略模型不接受的可选参数、完整响应超时、可操作且脱敏的错误信息、有限重试。
- Worker 原子抢占任务，回收中断后长期运行的任务，并阻止旧尝试或已取消任务覆盖新结果。
- 保存并测试支持分别反馈“保存成功”和“测试失败/冷却中”，不会因测试未完成而误报配置未保存。

## 验证结果

| 命令 | 结果 |
| --- | --- |
| `pnpm check` | lint、类型检查、207 项单元/集成测试、全部生产构建通过 |
| `pnpm test:e2e` | 163 项通过，9 项按原有设备/场景条件跳过 |
| `pnpm test:live` | 5 种 Chromium 屏幕尺寸、Firefox 桌面及 WebKit 手机，共 7 项真实链路通过 |
| `git diff --check` | 通过 |

真实链路使用构建后的前端、正式 API、独立临时数据库和测试文件服务。员工在同一条记录中将两个项目节点分别更新至 75% 和 50%，实际读取数据库对应的项目树确认结果；同时验证文件证据、审批和工时后续流程。

AI 测试运行实际配置服务与 Worker 处理器，供应商响应由测试桩控制，覆盖配置切换、密钥保留/清除、超时、限流、鉴权失败、重试次数、并发抢占、中断回收与取消竞态。没有使用生产供应商密钥发起真实付费请求，因此这些结果不代表已经验证线上供应商账户、网络或部署状态。

## 发布

新增迁移 `0013_famous_bastion.sql` 保留现有组织地址、模型和密文 Key，增加可配置生成参数，并移除数据库中的固定品牌与模型默认值。现有 Render Blueprint 的 `preDeployCommand` 运行 `pnpm db:migrate`，Web 与 Worker 在仓库 CI 通过后自动部署。

基础接入参数在 **工作智能 → 组织 AI 配置** 管理；API 与 Worker 仍须共享基础设施加密密钥 `AI_CONFIG_ENCRYPTION_KEY`。完整接入与切换说明见 [部署文档](deployment.md#组织-ai-配置与供应商切换)。
