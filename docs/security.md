# 安全与权限

认证使用 Argon2id 密码散列、不可逆 SHA-256 会话令牌、HttpOnly/Secure/SameSite cookie、CSRF token 和登录失败锁定。生产 API 统一启用 Helmet、严格 CORS、请求速率限制、日志敏感字段脱敏、参数 Zod 校验与结构化错误响应。`/healthz` 不依赖数据库，`/readyz` 需要数据库可用。

权限由角色的 grant 表驱动；每次请求都在服务端以 `permission + scopeKind + scopeId` 判定，不能相信路由或前端隐藏。组织级授权可覆盖窄范围，项目和成员范围只能匹配同一对象。团队列表、分析、审批、导出与附件读取均先收敛为调用者可见范围，再查询数据。

Owner 初始化通过 setup token 和 PostgreSQL 事务锁完成，数据库约束确保单组织只能存在一个 Owner。上线后立即轮换 `SETUP_TOKEN`，为 Owner 启用组织的二次认证策略，并定期撤销不再使用的会话。

密码重置使用一次性、只存 SHA-256 哈希的令牌，默认 60 分钟过期。重置令牌仅通过账号已验证的邮箱（SMTP）或 E.164 手机号（Twilio）发送，永不在 API 响应、前端状态或日志中返回；成功重置会消费令牌、清空锁定计数并撤销该用户全部既有会话。生产部署必须配置实际使用通道：邮箱需 `SMTP_HOST` 和 `SMTP_FROM`，短信需 `SMS_PROVIDER=twilio` 及全部 `TWILIO_*` 凭据；未配置时 API 以统一的 503 响应失败，不枚举账号，也不会伪造投递成功。

成员注册采用组织白名单邀请：具有成员管理权限的人创建邮箱或手机号身份，服务端先创建 `invited` 成员关系并只保存邀请令牌的 SHA-256 哈希，再通过对应真实通道发送一次性激活链接。接受邀请后才会设置密码并激活成员关系。只有该白名单中的身份可以加入组织；重发邀请会撤销旧令牌。

组织级 AI 的 Base URL、模型与 Key 由唯一 Owner 在敏感操作验证后管理。Key 使用独立的 `AI_CONFIG_ENCRYPTION_KEY` 经 AES-256-GCM 加密，数据库只保存密文；浏览器只能获知“是否已设置”，不能读取 Key。API 与 Worker 必须持有相同密钥，密钥丢失时应禁用并要求 Owner 重新录入组织 AI Key，而不是尝试恢复或记录原文。Base URL 在生产环境仅允许 HTTPS，并拒绝显式 localhost、私有 IP 与带凭据 URL；部署时仍应限制 Worker 的出站网络，避免 DNS 重绑定类风险。

## 双因素认证（TOTP）

成员可在“账户安全”中启用标准 RFC 6238 TOTP，兼容主流身份验证器。登录必须先通过密码，再使用有效期 5 分钟、一次性的挑战令牌提交第二因素；正式会话只在两步都完成后签发。验证码采用 30 秒步长、允许前后一个步长的时钟漂移，并记录已使用的计数器，防止同一验证码重放。

TOTP 共享密钥只在设置开始时通过已认证的 HTTPS 会话展示一次，数据库只保存以 AES-256-GCM 加密的密文。加密密钥由 `SESSION_SECRET` 域分离派生：生产环境不得轮换、丢失或跨环境复制该变量，否则已启用的因子将无法验证；如必须轮换，须在变更窗口内完成受控的因子重置/重新注册流程。撤销因子同时要求当前密码和当前动态验证码，并写入审计日志。当前版本尚未提供恢复码，组织应在启用前明确遗失设备的人工身份核验流程。

对象存储必须使用独立、最小权限的 bucket 凭据；bucket 只允许预签名 PUT/GET 所需动作，不设置公开读取。`S3_ENDPOINT` 既是服务端签名端点，也是生产 CSP 中允许的直传 origin。没有对象存储配置时，链接/文本证据可用，文件上传会明确返回不可用而不回退到本地磁盘。

对象存储 CORS 只允许 `WEB_ORIGIN`，方法限于 `PUT` 和 `GET`，请求头限于 `content-type`、`x-amz-checksum-sha256` 与签名所需的 `x-amz-*`；不要使用 `*` origin 或将 bucket 配为公开。上传签名有效期为 15 分钟，下载签名有效期为 5 分钟。
