# 安全与权限

认证使用 Argon2id 密码散列、不可逆 SHA-256 会话令牌、HttpOnly/Secure/SameSite cookie、CSRF token 和登录失败锁定。生产 API 统一启用 Helmet、严格 CORS、请求速率限制、日志敏感字段脱敏、参数 Zod 校验与结构化错误响应。`/healthz` 不依赖数据库，`/readyz` 需要数据库可用。

权限由角色的 grant 表驱动；每次请求都在服务端以 `permission + scopeKind + scopeId` 判定，不能相信路由或前端隐藏。组织级授权可覆盖窄范围，项目和成员范围只能匹配同一对象。团队列表、分析、审批、导出与附件读取均先收敛为调用者可见范围，再查询数据。

Owner 初始化通过 setup token 和 PostgreSQL 事务锁完成，数据库约束确保单组织只能存在一个 Owner。上线后立即轮换 `SETUP_TOKEN`，为 Owner 启用组织的二次认证策略，并定期撤销不再使用的会话。

密码重置使用一次性、只存 SHA-256 哈希的令牌，默认 60 分钟过期。普通自助重置令牌仅通过账号已验证的邮箱（SMTP）或 E.164 手机号（Twilio）投递，接口始终返回通用回执以防枚举；未配置通道时不会伪造投递成功。无外部通道的组织可以让唯一 Owner 在成员详情完成当前密码与可选 TOTP 二次验证后，为当前组织中的在职成员生成一条手工重置链接。该链接只在这次已授权响应中返回给 Owner，不写入数据库、审计载荷、查询缓存或服务器日志；Owner 必须通过私密渠道单独交付。无论来源为何，成功重置都会消费该用户全部未使用的重置令牌、同步更新该用户全部邮箱/手机号密码哈希、清空锁定计数并撤销全部既有会话。

## 邮箱与手机号生命周期

账号必须至少保留一个已验证的邮箱或手机号。初始化 Owner 时邮箱由一次性初始化令牌建立；可选手机号只会以待验证状态保存，不能因为表单填写而获得登录或恢复权限。受邀成员的白名单身份也会在设置密码、消费邀请令牌后才变为已验证。

成员可在 **账户安全** 中绑定邮箱或 E.164 手机号。新增、重发验证、移除都需要当前密码；已启用 TOTP 时还必须消费一组未使用的动态验证码。绑定令牌默认 24 小时有效（`CREDENTIAL_VERIFICATION_TTL_SECONDS`），只在数据库保存 SHA-256 哈希；验证成功会使旧绑定令牌失效。待验证标识不能登录或申请密码重置；系统拒绝删除最后一个已验证标识，并在数据库事务中锁住全部已验证标识以防多个设备并发绕过此保护。

新发出的邀请、密码重置和联系方式验证链接将令牌放在 URL fragment，而非 query string；fragment 不会随 HTTP 请求发送到服务器，前端读取后会立即清除。系统仍兼容此前已发出的 query-string 链接，但建议让用户重新发送新的链接。

成员注册采用组织白名单邀请：具有成员管理权限的人可以创建邮箱、手机号或两者同时作为同一成员的身份。服务端先创建 `invited` 成员关系并只保存邀请令牌的 SHA-256 哈希；默认的手工投递仅在当前授权操作中返回 URL-fragment 链接，自动邮件/短信投递必须显式选择且相应服务已完整配置。接受邀请后才会设置密码、验证本次邀请登记的全部联系方式并激活成员关系；任一已验证联系方式都可登录。只有白名单中的身份可以加入组织；重新生成邀请会撤销该成员全部旧邀请令牌。

组织级 AI 的 Base URL、模型与 Key 由唯一 Owner 在敏感操作验证后管理。Key 使用独立的 `AI_CONFIG_ENCRYPTION_KEY` 经 AES-256-GCM 加密，数据库只保存密文；浏览器只能获知“是否已设置”，不能读取 Key。API 与 Worker 必须持有相同密钥，密钥丢失时应禁用并要求 Owner 重新录入组织 AI Key，而不是尝试恢复或记录原文。Base URL 在生产环境仅允许 HTTPS，并拒绝显式 localhost、私有 IP 与带凭据 URL；部署时仍应限制 Worker 的出站网络，避免 DNS 重绑定类风险。

## 双因素认证（TOTP）

成员可在“账户安全”中启用标准 RFC 6238 TOTP，兼容主流身份验证器。登录必须先通过密码，再使用有效期 5 分钟、一次性的挑战令牌提交第二因素；正式会话只在两步都完成后签发。验证码采用 30 秒步长、允许前后一个步长的时钟漂移，并记录已使用的计数器，防止同一验证码重放。

TOTP 共享密钥只在设置开始时通过已认证的 HTTPS 会话展示一次，数据库只保存以 AES-256-GCM 加密的密文。加密密钥由 `SESSION_SECRET` 域分离派生：生产环境不得轮换、丢失或跨环境复制该变量，否则已启用的因子将无法验证；如必须轮换，须在变更窗口内完成受控的因子重置/重新注册流程。撤销因子同时要求当前密码和当前动态验证码，并写入审计日志。当前版本尚未提供恢复码，组织应在启用前明确遗失设备的人工身份核验流程。

对象存储必须使用独立、最小权限的 bucket 凭据；bucket 只允许预签名 PUT/GET 所需动作，不设置公开读取。`S3_ENDPOINT` 是服务端签名端点；`S3_BROWSER_ORIGIN` 是浏览器实际访问预签名 PUT/GET URL 的精确 origin，并且是生产 CSP 中唯一允许的对象存储直传与被动预览 origin。二者在虚拟主机式 bucket 中可能不同。没有完整对象存储配置或缺少该浏览器 origin 时，链接/文本证据可用，文件上传会明确返回不可用而不回退到本地磁盘。文件格式不以 MIME 白名单阻断：浏览器声明的类型仅作受控元数据记录，实际对象一律作为 `application/octet-stream` 保存。每次打开前都重新执行服务端行级与字段级权限检查；只有非 SVG 图片、音视频、PDF 和保守的纯文本/JSON/Markdown/CSV 使用五分钟内的 `inline` 签名在独立存储 origin 中展示，HTML、SVG、脚本、压缩包、Office 和未知格式始终以 `Content-Disposition: attachment` 强制下载。预览 iframe 使用空 sandbox，工作台不会执行附件脚本。每次上传都记录 SHA-256；网络或存储暂时失败会保留待上传状态并允许使用同一附件记录重新签发短时 PUT URL，只有已经验证的大小/哈希不一致才进入隔离状态。

对象存储 CORS 只允许 `WEB_ORIGIN`，并覆盖预签名上传所需的 `PUT`、`content-type` 与签名后的 `x-amz-meta-*` 请求头；不要使用 `*` origin 或将 bucket 配为公开。默认 `download_sha256` 模式会在上传后由服务端流式读取实际对象并重新计算 SHA-256，适配不提供 AWS flexible-checksum 响应头的 S3 兼容服务；仅在供应商明确支持时才使用 `provider_checksum`。上传签名有效期为 15 分钟，下载签名有效期为 5 分钟。
