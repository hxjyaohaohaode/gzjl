# 老板指定周期与薪资总览、工作明细下载

本次建立在已合并的完整优化及月度报销修复之上。周期由老板指定，月份只是快捷填入范围的方式，不强制自然月。

## 使用路径

1. 薪资管理的“薪资周期与批次”在成员方案和实时月度图表之前显示。选择一个月份可自动填入该月完整范围；起止输入始终可见，也可以直接修改到任意跨月周期，精确到秒。
2. 点击“保存老板指定周期”。周期采用组织时区，开始包含、结束不包含。整月的结束填写下月 1 日 00:00:00，完整涵盖本月最后一天，包括 23:59:59 这一秒内的事实，不在两个相邻周期之间重复计薪。
3. 点击对应周期的“计算并查看薪资总览”。计算成功后自动打开结果并定位到预览。预览 URL 保存 handoff 参数，刷新或从系统给出的入口进入都能回到该批次。默认显示每个周期最新有效计算，避免旧预估与新计算混在一起。
4. 点击“下载薪资总览及工作明细 Excel”。核对用统计表直接下载，不要求先锁定周期或为内部核对配置外部账号。未来结束的周期、待审和待复核金额会明确标示未确认，正式交接要求单独核对。缺方案成员出现在汇总中，金额留空并说明不能计算，不编造零工资。
5. 若计算后有工时、方案、费率、休息或报销调整变化，下载会拒绝混用旧金额和新事实，提示“更新计算并查看”。下载校验在相同的组织输入锁中完成，旧计算校验过程中临时产生的复算会随冲突回滚，不默默换批次。
6. 正式交接时展开外部人员映射，处理缺配置、待审核、更正和待复核事项，核对整批金额后确认并锁定。确认后的 Excel 与 CSV 原文件、批次号、规则和 SHA-256 继续保留；同一入口重取已确认原文件，不以当前事实重新生成历史文件。

## Excel 内容

第一张“薪资汇总”按成员唯一编号列出姓名、外部编号、周期、币种、已批准和待审工时、工作工资、奖励工资、补贴、已批准报销、其他调整、合计和金额状态。汇总和页面使用相同计算组成，精确十进制金额不被 JavaScript 或 Excel 浮点数改变。多币种分别汇总，不混加。

后续为“工资组成”“报销明细”“工作提交单”“工作证据目录”“规则与来源”。工作提交单包含与所选周期相交的事实、提交和审批状态、完整工作内容、结果、阻塞、下一步、项目节点和版本入口。跨周期整条记录不能直接将净工时加总为本期计薪工时，应核对组成中的实际切分计薪量。超长文本完整保留在续页。

未确认统计表在文件名、金额状态、规则说明和打印页脚中标示性质及生成时间；下载不会锁定原记录，不自动审批或在外部平台付款。服务端只允许组织 payroll.settle 且拥有组织 work.view_full_scope 的用户下载完整明细，普通成员不能通过猜测批次编号获取他人工资或正文。文件返回文件名、正确 MIME、no-store 与 SHA-256，浏览器验证后才发起下载。

本次没有新增 schema 迁移或删除业务数据；已有 0014 迁移的部署按既有 Render 配置更新代码即可。仍使用 Node.js 24+、pnpm 11+、PostgreSQL、既有私有对象存储。自然月快捷选择、指定历史月份、报销按所属周期展示、正式不可变批次和前一轮全部工时/审批/证据/AI 功能保留。
