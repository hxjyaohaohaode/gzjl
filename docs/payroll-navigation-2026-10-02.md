# 薪资与审批页面分工（2026-10-02）

原 `/payroll` 根据 `payroll.configure` 权限切换个人和管理界面，并把提交规则、周期操作、成员方案、团队预估与报销堆在同一页。现在菜单名称与页面职责固定，每个页面有独立地址，可以直接访问、刷新和返回。

| 入口 | 地址 | 页面职责 |
| --- | --- | --- |
| 我的薪资 → 本月薪资 | `/payroll` | 本人本月工时、工资预估、补贴与预测 |
| 我的薪资 → 历史工资单 | `/payroll/history` | 按日期查工资单、核对计薪组成、确认收款 |
| 我的报销 | `/reimbursements` | 本人申请、凭证、历史记录与处理进度 |
| 薪资管理 → 薪资总览 | `/payroll-management` | 团队预估、计薪人数、缺方案成员、待处理周期 |
| 薪资管理 → 成员方案 | `/payroll-management/plans` | 选择成员后编辑单价、补贴、倍率、奖励和生效日期 |
| 薪资管理 → 周期结算 | `/payroll-management/periods` | 周期查询、新建、计算、撤销和导出入口 |
| 薪资管理 → 结算设置 | `/payroll-management/settings` | 新建周期默认结算日期和计划导出时间 |
| 薪资交接预览 | `/payroll-management/runs/:runId` | 当前批次预检、金额核对、Excel 下载和正式交接 |
| 审批 → 工时审批 | `/approvals` | 工时审批及工时更正 |
| 审批 → 报销审批 | `/approvals/reimbursements` | 其他成员尚未处理的报销申请 |
| 审批 → 报销审批 → 审批记录 | `/approvals/reimbursements/history` | 按日期查看他人已批准或驳回的报销、凭证和审批说明 |
| 工时提交规则 | `/organization/work-policy` | Owner 设置补录天数和每月提交期限 |

## 交互与权限

- 薪资管理要求组织级 `payroll.configure`；实际计算、交接预览和导出仍要求组织级 `payroll.settle`。完整工作明细导出仍要求组织级 `work.view_full_scope`。
- 工时审批与报销审批分别按 `work.review` 和组织级 `payroll.settle` 显示。只有报销审批权限的用户从审批入口直接进入报销队列，不请求工时审批数据。
- “我的报销”明确请求 `ownOnly=true`，服务端在数据库查询及分页前限定本人，即使调用者是薪资审批人也不会混入他人记录。审批队列排除本人申请，保留不能自审及他人草稿不可见的限制。
- 周期列表月份写入 `month` 查询参数，刷新和浏览器返回后保留。列表筛选与新建周期的月份各自独立。有周期时，新建表单默认折叠。
- 成员方案先选人再编辑；提交期间冻结成员选择与表单，保存后显示成功状态。
- 个人页面不挂载组织管理、报销或工时规则组件；交接详情不再嵌在周期列表下方。

## 旧链接与金额规则

`/payroll?source=...` 自动定位到历史工资单并保留来源参数；`/payroll?handoff=...` 自动进入独立交接页；`/payroll#reimbursement-...` 自动进入报销详情。旧 `view=own` 链接仍显示本人薪资。

本次不改变工资、补贴、报销入账、金额精度和已确认导出文件的计算规则，没有数据库迁移。工资页面继续展示获批报销对金额的影响，报销申请和审核在各自页面操作。
